# ACE Session Packet — local-storage deployment

*For a Cowork panel or a Claude Code session opened at the repo root. Instruction to give it: "Execute deploy/DEPLOY_PACKET.md". Format: `templates/SESSION_PACKET.md`.*

## Session ID

`P-DEPLOY<YYYYMMDD>` — use today's date. The exit package goes to `X-DEPLOY<YYYYMMDD>`.

## Panel type

Produce

## Objective

Deploy ACE on this machine: this repo's engine plus three empty local stores (control plane, content plane, hub vault). Verify the deployment and schedule the daily backup. Nothing is migrated or copied from another deployment.

## Stop condition

The packet ends in one of two ways:

- `python deploy/verify_deploy.py` exits 0, and the exit package is written; or
- a blocking decision is put to the owner, recorded, and the session stops.

## Visible roots

- The repo root: read; write only under `deploy/` if a fix is genuinely needed — propose it, don't apply it.
- The three target store folders the owner names in step 1.
- Nothing else. Do not scan other drives or folders.

## Workspace manifest

None — a fresh deployment has no manifest. The manifest loop creates it later.

## Authoritative files

- `CLAUDE.md` — operating contract.
- `deploy/README.md` — procedure.
- `spec/11_STORAGE_AND_FILING.md` — layout and writer matrix.
- `spec/08_WORKSPACE_ATLAS.md` — access classes. On a new machine, treat every root not named in this packet as off-limits.
- `spec/10_OPEN_QUESTIONS.md` — open rulings. **Never decide one.**

## Previous resume state

None.

## Known missing context

Ask the owner for anything not given. Do not guess.

- The three store paths.
- The backup destination (local or offline only).
- Whether the control plane gets a private remote.
- Whether Obsidian is installed.
- Whether `CLAUDE.md`'s owner-specific lines need adapting for this owner.

## Write permissions

| Allowed | Requires the owner's explicit yes first | Forbidden |
|---|---|---|
| Create folders/files inside the three store paths via `deploy/bootstrap_stores.py --apply` | Setting the user environment variables (`deploy/ace_env.example.ps1`, edited); registering the scheduled task (`deploy/register_backup_task.ps1`); adding a control-plane remote | Deleting or overwriting anything; writing outside the visible roots; adding a remote to the content plane; copying another deployment's state/content; activating `ace tick` or any other loop (ruling R5-2); entering credentials |

## Steps

1. **Ask** for the store paths and the backup destination. Recommend three sibling folders on one local disk, e.g. `D:\ACE\ACE_storage`, `D:\ACE\ACE_local`, `D:\ACE\ACE_hub`. Confirm they are separate and not nested.
2. **With a yes:** copy `deploy/ace_env.example.ps1`, set the paths, run it, then start a new shell, so the variables are visible.
3. **Plan:** run `python deploy/bootstrap_stores.py` and show the owner the plan. If a target folder already holds files, say so and stop for a decision. The bootstrap never overwrites, but the owner should know.
4. **Create:** run `python deploy/bootstrap_stores.py --apply`. This also initializes the hub: root note with marks, `.obsidian/app.json` sending new notes to `inbox/`, and the four views generated by the engine.
   - **If Obsidian is installed**, tell the owner to *Open folder as vault* on the hub path. Obsidian Sync is the owner's own in-app choice; never touch account credentials.
5. **Verify:** run `python deploy/verify_deploy.py` and report the full table.
   - FAIL → fix within the write permissions, or stop and ask.
   - WARN → report it; it does not block.
6. **With a yes:** run `.\deploy\register_backup_task.ps1 -BackupDest '<dest>'`, then re-run step 5 — the backup row should read PASS.
7. **Exit package:** write `<ACE_STORE>/outbox/X-DEPLOY<YYYYMMDD>/EXIT_PACKAGE.json` per `schemas/panel_exit_package.schema.json`.
   - `panel_type`: `produce`.
   - `outcome`: one line plus the verify verdict.
   - `sources_seen`: the visible roots.
   - `sources_not_seen`: everything else.
   - `evidence_created`: `sha256:` pointers to the verify output, if saved.
   - `next_action`: the owner validates with `python engine/ace_engine.py validate X-DEPLOY<YYYYMMDD>`.
   - `proposed_state_changes`: `[]`.

   Do not run `validate` yourself.

## Expected artifact

Three scaffolded stores; a verify report with no FAIL; a registered `ACE_backup_daily` task (if approved); one exit package in the outbox.

## Acceptance criteria

- `verify_deploy.py` exits 0.
- The content plane has no git remote.
- The control-plane remote, if any, is PRIVATE.
- Nothing outside the three stores was written. The only exceptions are the user environment variables and the scheduled task, and only if approved.
- No file anywhere was deleted or overwritten.
- No loop other than the backup was scheduled.

## Outbox path

`<ACE_STORE>/outbox/X-DEPLOY<YYYYMMDD>/EXIT_PACKAGE.json`

## Scope declaration required from panel

The panel must state:

- what it inspected;
- what it did not inspect;
- its confidence in completeness;
- every owner decision taken, quoted;
- every decision left open.
